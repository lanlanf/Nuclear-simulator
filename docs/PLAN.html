1. Concept

This is a miniature reactor control panel. The reactor physics runs as a real-time math model on the Arduino itself, not on a PC.

  • Potentiometer: sets the control rod position. A rod-worth curve converts that position into reactivity \(\rho\).
  • Arduino: solves the 6-group point kinetics equations (PKE) plus a temperature feedback model.
  • LEDs: show the plant state (subcritical, critical, supercritical, warning, SCRAM).
  • Buzzer: sounds on high power, high temperature or a short period.
  • Servo: physically shows how far the rods are inserted.
  • SCRAM button: drives the rods in. The trip latches until you reset it.
  • Serial Plotter / CSV log: shows power, period, reactivity and temperature live.
Headline claim: six delayed neutron groups and temperature feedback, solved on a microcontroller with a stiffness-aware implicit integrator, and validated against a SciPy reference solution.
Approach: write and test the C++ math on a PC first, then connect the Arduino. The physics code is shared, so the Arduino runs the exact code you validated (see §9).

2. Key terms (glossary)

Reactor physics

Fission
A heavy nucleus (U-235) absorbs a neutron and splits. It releases energy and about 2.4 new neutrons.
Chain reaction
Neutrons from one fission cause more fissions. Power is proportional to how many neutrons are present.
Neutron population \(n\)
How many neutrons are in the core. In this model it is normalized so \(n=1\) means 100% power.
Multiplication factor \(k\)
Neutrons in one generation divided by neutrons in the previous one.
Subcritical / critical / supercritical
\(k<1\): power falls. \(k=1\): power stays constant. \(k>1\): power rises.
Reactivity \(\rho\)
\(\rho=(k-1)/k\), how far the core is from critical. Negative is subcritical, 0 is critical, positive is supercritical.
pcm
“Per cent mille,” \(10^{-5}\) of reactivity. 100 pcm = 0.001.
Dollar (\(\$\))
Reactivity divided by \(\beta\). \(\$1\) = \(\rho=\beta\approx 0.0065\) = 650 pcm. Operators think in dollars and cents.
Prompt neutrons
Neutrons released instantly at fission, about 99.35% of them.
Delayed neutrons
About 0.65% of neutrons, released seconds to a minute later by radioactive fission fragments. They are what makes a reactor controllable.
Delayed neutron fraction \(\beta\)
The fraction of neutrons that are delayed: \(\beta\approx 0.0065\) for U-235.
Precursors \(C_i\)
The fission fragments that later emit delayed neutrons. They are grouped into 6 “groups” by half-life (0.2 s to 56 s).
Decay constant \(\lambda_i\)
How fast a precursor group decays: \(\lambda=\ln 2/t_{1/2}\).
Prompt neutron generation time \(\Lambda\)
Average time between one generation of prompt neutrons and the next, about \(10^{-4}\) s in a thermal reactor.
Point kinetics equations (PKE)
Seven coupled ODEs: one for \(n\) and six for the \(C_i\). They treat the whole core as one point with no spatial shape.
Prompt critical
\(\rho\ge\beta\) (\(\ge\$1\)). The reactor is critical on prompt neutrons alone, so power rises in milliseconds. This is the dangerous regime (SL-1, Chernobyl).
Reactor period \(T\)
Time for power to grow by a factor of \(e\) (2.718). Long period = slow and safe; short period = fast and dangerous.
Startup rate (SUR)
Power growth in decades per minute (DPM): \(\text{SUR}=26.06/T\). Real consoles show it.
Prompt jump / prompt drop
An almost instant change in power when reactivity steps, before the delayed neutrons catch up. The size of the jump is \(\beta/(\beta-\rho)\).
Inhour equation
The exact relationship between a reactivity step and the stable period that follows. Used to check the simulator.
Control rod
Neutron-absorbing rod. Inserting it lowers \(\rho\); withdrawing it raises \(\rho\).
Rod worth (integral / differential)
Integral worth: total reactivity change from moving a rod. Differential worth: reactivity per cm of travel, which is largest at mid-core and produces the S-curve.
SCRAM
Emergency shutdown that drives all rods in at once.
Trip / setpoint
An automatic SCRAM that fires when a measurement crosses a limit (high power, high temperature, short period).
Temperature coefficient \(\alpha_T\)
Reactivity change per kelvin. A negative value means a hotter core loses reactivity, so the reactor self-stabilizes.
Feedback
The reactor's own state (temperature) changing its reactivity.
Neutron source \(S\)
A small external neutron supply, so a shut-down reactor still has a measurable neutron level to start up from.
Annunciator
A panel of labeled alarm lights that latch on until the operator acknowledges them.

Math and numerical methods

ODE
Ordinary differential equation: a rule for how a quantity changes over time, \(dy/dt=f(y,t)\).
Time step \(h\) (or \(\Delta t\))
How far forward in time the solver jumps each step, e.g. 10 ms.
Explicit (forward) Euler
\(y_{k+1}=y_k+h\,f(y_k)\). Uses the slope at the start of the step. Simple, but can blow up.
Implicit (backward) Euler
\(y_{k+1}=y_k+h\,f(y_{k+1})\). Uses the slope at the end of the step, so you have to solve for \(y_{k+1}\). Stable for stiff problems.
RK4
Fourth-order Runge–Kutta, a more accurate explicit method. It is still unstable on stiff problems at large steps.
Stiff
See §3. A system with both very fast and very slow behavior, which forces explicit methods to take tiny steps.
Stability
Whether numerical errors die out (stable) or grow without bound (unstable) as you keep stepping.
Eigenvalue (of an ODE system)
The natural growth or decay rates of the system. A large negative eigenvalue means a very fast decay.
Order of accuracy / convergence
How the error shrinks as \(h\) shrinks. First order: halving \(h\) halves the error.
Crank–Nicolson
Averages explicit and implicit Euler. Second-order accurate.
Prompt jump approximation (PJA)
Sets \(dn/dt\approx0\) to remove the fast part. Accurate below about 0.5$, and breaks down at \$1.
Radau / BDF
High-accuracy implicit methods that SciPy uses as the reference “truth.”
Float (32-bit)
Single-precision number with about 7 significant digits. On the Uno R3, double is the same as float.
EMA filter
Exponential moving average, \(y\leftarrow y+a(x-y)\). Smooths noisy pot readings.

Electronics and microcontroller

Microcontroller (MCU)
A small computer on one chip: CPU, memory and I/O pins.
Clock speed
CPU cycles per second. The R3 runs at 16 MHz, so one cycle is 62.5 ns.
Flash / SRAM / EEPROM
Flash holds the program. SRAM holds variables while running and is wiped on reset. EEPROM holds small data that survives power-off.
FPU
Floating-point unit: hardware for decimal math. Without one (R3), float math is done in software and is about 100× slower.
ADC / analogRead
Converts a voltage (0–5 V) to a number (0–1023 at 10-bit; this build reads 14-bit, 0–16383).
PWM
Pulse-width modulation: switching a pin on and off quickly to fake an analog level. Used for LED brightness and servo signals.
Voltage divider
How a pot works: \(V_\text{out}=V_\text{in}\cdot R_2/(R_1+R_2)\).
Current-limiting resistor
\(R=(V_{cc}-V_f)/I\), protects the LED and the pin.
Interrupt / ISR
A hardware signal that pauses the main loop to run a short function, so the SCRAM button is never missed.
Debounce
Ignoring the rapid on/off chatter of a mechanical button for 20–50 ms.
INPUT_PULLUP
Internal resistor that holds a pin HIGH, so a button to ground reads LOW when pressed.
I2C
Two-wire bus (SDA/SCL) for displays and sensors.
Baud
Serial bits per second. 115200 baud is about 11.5 KB/s.
Brownout
A supply-voltage dip (e.g., servo stall current) that resets the MCU.
Latch
Stays in a state (tripped) until it is explicitly reset.
Fixed timestep / non-blocking loop
Run the physics every exactly 10 ms using millis(), never delay().

3. What “stiff” means, and why it matters here

A system is stiff when it contains processes on very different time scales, and the fast one has already died out but still controls which step sizes are stable.

The reactor has two clocks:

  • Prompt neutrons react in about \(\Lambda=10^{-4}\) s. Their rate is \((\beta-\rho)/\Lambda\approx 65\ \text{s}^{-1}\), a time scale of about 15 ms.
  • Delayed precursors evolve over 0.2–80 s. The slowest rate is \(0.0124\ \text{s}^{-1}\).

The rates differ by more than \(10^4\). You only care about the slow behavior, which is what you see on the plot, but explicit methods must still take steps small enough to follow the fast part. Otherwise they blow up.

Tiny worked example

Take \(dy/dt=-1000\,y\) with \(y_0=1\), whose true solution decays to 0 almost instantly. Use \(h=0.01\) s:

Explicit Euler
\(y_{k+1}=y_k+h(-1000y_k)=(1-10)\,y_k=-9\,y_k\)
\(1,\,-9,\,81,\,-729,\dots\) explodes.
Implicit Euler
\(y_{k+1}=y_k+h(-1000y_{k+1})\Rightarrow y_{k+1}=\dfrac{y_k}{1+10}\)
\(1,\,0.091,\,0.0083,\dots\) decays correctly.

For explicit Euler the stability rule is \(h<2/|\text{fastest rate}|\). For this reactor that means

\[\Delta t<\frac{2\Lambda}{\beta-\rho}\approx 31\text{ ms at }\rho=0\]

That limit shrinks to about 5 ms right after a −$5 SCRAM. Implicit Euler has no step-size limit, which is why this project uses it. Running explicit Euler at 40 ms on purpose and watching it fail makes a good figure for your report (test V7).

  • Something you can show: at zero power the core is 30 K cooler, which adds +3.46 dollars. The reactor therefore goes critical at about 28% withdrawn during a cold startup, compared with 50% at full power.
  • Overcooling demo (use the coolant pot as \(T_\text{cool}\)): lower \(T_\text{cool}\) by 10 K with the rod fixed. The colder core gains reactivity, so power rises until \(T\) is back at \(T_\text{ref}\), at \(P=1+10/30\approx1.33\). The panel's coolant pot stops at −5 K (\(P\approx1.17\)), below the 1.20 trip; sim_cli and the tests show the full 10 K. This is why the MTC has a lower limit, typically about −80 pcm/°C: in a main steam line break the coolant cools quickly, and a strongly negative MTC turns that into a large positive reactivity insertion [R14].
  • Expected dynamics (slide 17): a reactor at power is highly damped. After a small step, power rises, overshoots, then settles where the net \(\rho=0\). The first draft (150 s lag) overshot about 80%. 6. Numerical method

Chosen: backward (implicit) Euler with closed-form elimination. It is unconditionally stable, needs no matrix solve, and costs about 60 flops per step.

  1. \(C_i^{k+1}=\dfrac{C_i^k+h\beta_in^{k+1}/\Lambda}{1+h\lambda_i}\)
  2. Substitute into the \(n\) equation, which leaves one scalar equation: \[n^{k+1}=\frac{n^k+h\sum_i\dfrac{\lambda_iC_i^k}{1+h\lambda_i}+hS}{1-\dfrac{h(\rho-\beta)}{\Lambda}-\dfrac{h^2}{\Lambda}\sum_i\dfrac{\lambda_i\beta_i}{1+h\lambda_i}}\]
  3. Update each \(C_i^{k+1}\) using the new \(n^{k+1}\).

// reactor.h — shared by the desktop test program and the Arduino sketch
const float beta_i[6] = {0.000215,0.001424,0.001274,0.002568,0.000748,0.000273};
const float lam_i[6]  = {0.0124,0.0305,0.111,0.301,1.14,3.01};
const float BETA = 0.0065, LAMBDA = 1e-4;
float n = 1.0, C[6];

void initPrecursors() { for (int i=0;i<6;i++) C[i] = beta_i[i]*n/(lam_i[i]*LAMBDA); }

void pkeStep(float rho, float h, float S) {
  float num = n + h*S, den = 1.0 - h*(rho - BETA)/LAMBDA;
  for (int i=0;i<6;i++) {
    float d = 1.0 + h*lam_i[i];
    num += h*lam_i[i]*C[i]/d;
    den -= h*h*lam_i[i]*beta_i[i]/(LAMBDA*d);
  }
  n = num/den;
  if (n > 1e6) n = 1e6;   // float-overflow guard past prompt critical
  for (int i=0;i<6;i++) C[i] = (C[i] + h*beta_i[i]*n/LAMBDA)/(1.0 + h*lam_i[i]);
}

Period estimate: \(T=\Delta t/\ln(n_k/n_{k-1})\), smoothed with an EMA. The short-period trip fires at \(|T|<10\) s.

7.2 What the MCU is expected to do (its job list)

Every 10 ms, the Arduino must:

  1. Read 2 pots (ADC), filter them, and rate-limit the rod.
  2. Compute rod reactivity from the S-curve (one sin() call) plus temperature feedback.
  3. Run one implicit Euler PKE step (7 ODEs) and one thermal step.
  4. Estimate the period and SUR (one log() call).
  5. Check trips: high power, high temperature, short period, and the SCRAM button flag. Latch if any fire.
  6. Update the LEDs, buzzer and servo angle.

Every 100 ms it prints one line to the Serial Plotter. Every 100–200 ms it refreshes the OLED, if one is fitted.

It must also never miss a SCRAM press (handled by an interrupt), and never fall behind real time (each step must finish in under 10 ms).

8.3 Electrical design (the E&M part of ENGR 217)

  • LED resistor: \(R=(V_{cc}-V_f)/I\).
    • R3: \((5-2)/220\approx13.6\) mA.
    • R4: use 1 kΩ, which gives about 3 mA and stays under the 8 mA pin limit.
  • Pot: works as a voltage divider, \(V=5\cdot\text{ADC}/16383\) at 14 bits.
  • Servo: give it a separate 5 V supply with a shared ground [H7]; never power it from the board's 5 V pin [H4]. The bulk capacitor prevents brownout resets.
  • Button: the ISR only sets a volatile flag. Debounce in loop().
  • Extra E&M ideas if you want course credit:
    • Measure servo current with a multimeter.
    • Add an RC low-pass filter on the pot and compute its cutoff frequency \(f_c=1/(2\pi RC)\).
    • Scope the PWM waveform.

9. Software architecture

9.1 Folder layout: physics is shared, I/O is separate

Nuclear Reactor Simulator/
  reactor.h / reactor.cpp    physics only: step(rodFraction, dt) → power, temp, period
  desktop/main.cpp           runs scripted scenarios on the PC, writes CSV
  reference/pke_scipy.py     SciPy Radau reference solution
  arduino/reactor_panel.ino  reads pots, drives LEDs/servo, calls the same reactor.h
Rules for reactor.h, so the identical file runs on the Arduino:
  • Use float, not double.
  • No STL (std::vector, iostream, new); use fixed arrays only.
  • No millis(). Pass dt in as an argument.

Compiler on Windows: MSYS2 + MinGW g++, Visual Studio Build Tools, WSL, or an online compiler (OnlineGDB) to start.

9.2 Arduino main loop

loop():
  every DT = 10 ms (millis(), never delay()):
    read pots → EMA → rate-limit rod → rho_rod(x)
    rho = rho_rod + alpha_T*(T - T_ref)        (forced to −5 dollars if tripped)
    pkeStep(rho, DT, S)
    thermal step (backward Euler)
    period / SUR estimate
    trips: P > 1.2, T > T_max, |period| < 10 s, SCRAM flag → latch
    outputs: LEDs, buzzer, servo = rod %, OLED (every 100–200 ms)
  every 100 ms: Serial.print("P:..,rho:..,T:..,SUR:..")   → Serial Plotter

State machine (as built): the board powers up at full power (critical, rod at 50%, no trip latched). POWER → TRIPPED (latched) → RESET (only with rods and rod pot fully in) → STARTUP → CRITICAL/POWER. A rod stop blocks withdrawal while any warning is up.
